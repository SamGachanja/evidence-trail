# Reference solution

The [full expected JSON](reference-output.json) was generated by actually executing [reference.py](reference.py) on CPython 3.14.0 linked against SQLite 3.50.4. This executable is kept separate from the model's isolated workspace. The model receives the program and question, not its output. Audit entries are sorted event strings so the answer does not depend on trigger firing order.

## Change-count ledger

`base_total_changes` is 6: three seeded parent rows and three seeded child rows. The last seed INSERT changes three rows, so `changes()` at S0 is 3.

| S0 | 0 | 0 | Seeded state, outside a transaction. |
| S1 | 5 | 5 | Replacement removes parent 1; two child deletions and their two audit inserts count, as does the new parent. Replacement's implicit parent deletion is excluded; its parent-delete trigger is disabled. |
| S2 | 1 | 6 | `OR FAIL` retains row 5, stops at row 6's uniqueness conflict, and never attempts row 7. |
| S3 | 0 | 6 | Savepoint rollback restores rows and audit entries; cumulative change accounting is not rewound. |
| S4 | 2 | 8 | Parent 8 and invalid child 801 are inserted; the explicit deferred-constraint COMMIT fails and leaves the transaction open. |
| S5 | 2 | 10 | Deleting child 801 plus its audit insertion repairs the violation; COMMIT succeeds. |
| S6 | 4 | 14 | The failed UPDATE contributes no retained changes; replacement cascades child 201, records child and parent audit entries with recursive triggers enabled, and inserts parent 9. |
| S7 | 0 | 14 | ROLLBACK restores the S5 row state, while cumulative accounting remains 14. |
| S8 | 6 | 20 | The attempted foreign-key disable occurs in an open transaction and has no effect. Parent 1, its two children, and three audit inserts count. |

After S0, `changes()` is 1 at every recorded checkpoint. Read-only snapshot queries and transaction-control statements do not replace that last DML count. The failed unique UPDATE is followed by a successful INSERT before S6, so its zero count is not the count observed at S6.

The four caught extended error names, in order, are UNIQUE, FOREIGNKEY, UNIQUE, and FOREIGNKEY, each prefixed with `SQLITE_CONSTRAINT_`.

## Why the commits differ

SQLite's failed explicit COMMIT for a deferred foreign-key violation leaves the transaction active, so S4 still contains the invalid child. See [deferred foreign-key constraints](https://www.sqlite.org/foreignkeys.html#fk_deferred).

Python's connection context manager attempts a commit on normal block exit. If that commit fails, it rolls back. With Python `autocommit=False`, completing a transaction opens another one; therefore S8 and S9 both report `in_transaction=true`, even though the preceding successful context block committed and the failing one rolled back. See [connection context-manager behavior](https://docs.python.org/3.14/library/sqlite3.html#how-to-use-the-connection-context-manager) and [Python transaction control](https://docs.python.org/3.14/library/sqlite3.html#transaction-control-via-the-autocommit-attribute).

## Rules to keep separate

- [SQLite conflict handling](https://www.sqlite.org/lang_conflict.html) distinguishes FAIL's preserved earlier rows, ABORT's statement rollback, and REPLACE's auxiliary deletions and trigger behavior.
- [Direct change counts](https://www.sqlite.org/c3ref/changes.html) exclude auxiliary trigger/cascade/replacement changes, whereas [total change counts](https://www.sqlite.org/c3ref/total_changes.html) include trigger and foreign-key actions but not REPLACE's auxiliary deletes. The executed reference additionally establishes how the pinned runtime's cumulative counts behave after rollback.
- [The foreign-key pragma](https://www.sqlite.org/pragma.html#pragma_foreign_keys) cannot be toggled inside an active transaction. The failed toggle at S8 and successful toggle at S10 therefore have different consequences.

The complete rows, audit multisets, transaction flags, and foreign-key check results are in the JSON reference. Runtime output, a documented rule, and a manually checked count ledger together support the reference; a vague claim that a counter “resets on rollback” does not.
